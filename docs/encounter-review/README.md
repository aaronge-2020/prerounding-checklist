# Source-linked encounter preparation

This increment develops a specific product hypothesis: an encounter workspace
can reduce repeated chart review and loss of follow-up context even when a
clinician uses another product for final note writing. It does not establish
superiority over Doximity, clinical effectiveness, or broad adoption.

## Workflow

1. Save and privacy-review chart sources using the existing import workspace.
2. Open **Prepare & follow-up** above the selected packet's source editor.
3. In **Find a source**, choose any explicitly saved packet and source. Select
   an exact passage and track it as Follow-up, Clarify, or Verify today.
   Structured Plan sections also provide one-click tracking of individual
   nonempty lines. These are quoted plan passages, not inferred orders/tasks.
4. Record a decision for the selected packet. Attach a separate saved passage
   as supporting evidence when available. Attaching evidence does not mark a
   task completed. Later status changes retain valid attached evidence.
5. Use **Compare packets** to inspect full saved sources side by side, with
   exact changed lines highlighted. Missing text does not mean resolution.
6. Copy a labeled review brief or insert `@encounter-review` into an existing
   prompt template. It is optional; no chart text is added to prompts silently.

The note writer links back to preparation for its selected packet. The patient
roster shows the number of tracked items. The existing packet system is reused;
no additional route, account, service, or model download is required.

## State and privacy contract

- `patient.encounterReview` contains items, exact source references, explicit
  per-packet decision history, and deduplicated immutable snapshots of the
  **retained de-identified** source versions used by those references. No raw
  paste, active-review original, free-text task input, or external AI output is
  introduced. Unreferenced snapshots are pruned during vault normalization.
- References are bound to patient, packet, and source identity. Current saved sources remain authoritative. Full-source equality, including
  context outside the selected excerpt and saved source metadata, is checked against the referenced
  snapshot. Unchanged saves do not invalidate decisions merely because their
  timestamps changed. Changed/missing sources or changed evidence invalidate
  current status and withhold their quotations from transferable briefs.
- Sources with residual warnings or explicitly skipped de-identification
  cannot create tracked items or supporting references. Existing local privacy
  review must be completed first.
- Each packet's latest explicit decision applies only to that packet. Earlier
  decisions remain inspectable in the history and are not silently inherited.
  Previously closed follow-ups are labeled historical and excluded from the
  attention filter while their sources remain valid. This avoids reopening
  completed work at every encounter. Recording Pending explicitly reopens a
  follow-up; verification of a current finding remains packet-specific.
- Briefs omit user-entered patient/packet labels and local record timestamps.
  Quotations are marked historical/supporting; statuses are clinician-recorded.
  The existing external-request scan/review gate is unchanged.
- Persistent records use the existing encrypted vault; older records normalize
  to an empty review workspace. Lock/patient changes clear the review DOM and
  session choices. Failed encrypted writes roll back the in-memory mutation.
- Comparisons pair only explicit note-section identities or unique matching
  source kind/label/category groups. Duplicate groups are not arbitrarily
  paired. The line-diff working set is bounded; large comparisons preserve all
  source text and highlight the differing middle without semantic inference.

## Verification

`npm.cmd run test:encounter-review` covers exact passage tracking, duplicate
prevention, source/evidence invalidation, unchanged-save stability, snapshot
deduplication/pruning, explicit decision history, packet-specific status,
privacy gates, encryption round-trip, prompt scope, ambiguous comparisons,
and lossless large-document comparison. The browser portion exercises real
clicks, source/evidence selection, status changes, clipboard output, failed
storage rollback, one-click Plan tracking, note-writer navigation, patient
switching, lock/unlock, mobile viewport bounds, and absence of external
requests. Fixtures are synthetic; no patient message was copied into them.

Desktop and mobile screenshots in this folder are generated by that browser
test. They document the synthetic workflow, not a clinical usability study.

## Remaining validation

The next adoption test should compare the complete workflow against direct use
of an approved existing tool on the same synthetic cases. Include import,
privacy review, maintaining the workspace, and correcting output in total task
time. Measure missed follow-up items, unsupported current findings, and review
burden. Keep the workflow only if its benefit exceeds its extra maintenance.

This is a personal preparation aid. It has no EHR synchronization, inferred
timeline, team task assignment, reminder delivery, or automatic determination
that a test was ordered/completed. Clinical review remains necessary.
